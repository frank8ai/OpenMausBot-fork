# Netflix Chaos Injection Specification (混沌工程故障注入规范)

## 1. 稳态假设原理 (Steady-State Hypothesis)
混沌工程并非盲目搞破坏，而是在受控实验下探寻系统韧性边界：
1. **定义稳态指标**: 系统在正常负载下的特征（响应延迟、业务成功率、无白屏崩溃）。
2. **假设稳态持续**: 假设即使在出现服务延迟、节点下线或上游熔断时，稳态仍能维持（或受控优雅降级）。
3. **引入现实变量**: 模拟生产环境必然发生的硬件损坏、网络抖动与第三方限流。
4. **证伪与加固**: 发现隐藏漏洞并在代码层实施断路器（Circuit Breaker）、指数退避与优雅回退。

## 2. 前端与无头 Agent 领域的四大注入模式

### 2.1 延迟与乱序 (Latency & Out-of-Order Responses)
- **模拟目标**: 模拟用户在移动蜂窝网络下的 2000ms 高延迟及两个并发请求的响应乱序。
- **验证重点**: 页面是否出现竞态条件（Race Condition，如旧请求覆盖新搜索结果）。

### 2.2 突发限流 (HTTP 429 Rate Limiting)
- **模拟目标**: API 网关触发 `Retry-After: 3` 头。
- **验证重点**: 客户端 SDK 是否按标量暂停并静默重试，而非疯狂刷屏重试压垮服务器。

### 2.3 异常上游中断 (HTTP 500 / 502 / Empty Payload)
- **模拟目标**: 响应体非合规 JSON，或是网关直出 502 HTML。
- **验证重点**: JSON.parse 是否导致 UI 进程直接崩溃，容错边界是否捕获。

### 2.4 离线分区 (Network Offline Partition)
- **模拟目标**: 强行切断 WebSocket 与 HTTP 连接。
- **验证重点**: 是否触发离线存储，网络恢复后是否正确重放（Replay）。
