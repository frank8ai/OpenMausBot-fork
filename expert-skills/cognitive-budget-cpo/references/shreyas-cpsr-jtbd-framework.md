# Shreyas Doshi CPSR 栈式排序与 Tony Ulwick JTBD 机会算法

## 1. 客户问题栈式排序 (Customer Problem Stack Ranking, CPSR)

### 为什么传统需求调研充满谎言？
当向用户单独询问“你是否想要功能 X？”时，80% 的用户都会出于客套或当下注意力聚焦而回答“想要”。这被称为**聚焦错觉 (Focusing Illusion)**——当用户专注于某个问题时，会下意识高估其重要性。

### CPSR 核心实战法则：
1. **构建问题全景堆栈**：收集目标客群在日常工作中真实面临的 10~20 个最棘手挑战（涵盖效率、协作、合规、成本等）。
2. **强制堆栈排序**：要求受访者对其进行绝对优先级排序（Rank 1 至 Rank N），不允许出现平局。
3. **生死线判定**：
   - **Top 1~3 (核心痛点区)**：用户每天为此痛苦，具备强烈的付费意愿与迁移意愿。只有落在此区间的需求才获准立项。
   - **Rank 4~7 (次要关注区)**：用户觉得有用，但不愿为此付费或改变既有使用习惯。
   - **Rank 8+ (噪音与虚荣区)**：纯属注意力幻觉，一律归入 Killed Scope。

## 2. Tony Ulwick 结果驱动创新 (JTBD) 机会算法

### 机会得分数学方程：
$$\text{Opportunity Score } (O) = \text{Importance } (I) + \max(\text{Importance } - \text{Satisfaction }, 0)$$

- **重要度 (Importance, I)**：取值 1~10，衡量该任务对用户成功的重要性；
- **满意度 (Satisfaction, S)**：取值 1~10，衡量用户对当前已有解决方案的满意程度。

### 投资回报决策矩阵：
| 机会得分区间 | 市场属性 | 战略裁决与行动指引 |
|---|---|---|
| **$O \ge 15$** | **极端未被满足区 (Extreme Underserved)** | 战略必争之地！具备颠覆性产品机会，全量倾斜研发算力与资源推进。 |
| **$12 \le O < 15$** | **黄金投资区 (Core Opportunity)** | 高回报投资区，架构设计与工程交付的核心主线。 |
| **$10 \le O < 12$** | **渐进改良区 (Modest Improvement)** | 仅做低成本增量修补，不分配重大架构预算。 |
| **$O < 10$** | **过度服务区 (Overserved / Noise)** | **一律绞杀！** 当前解决方案已足够优秀，增加新功能只会带来认知负担与系统臃肿。 |
