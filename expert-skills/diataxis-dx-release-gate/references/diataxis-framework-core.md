# Daniele Procida Diataxis 4 象限架构深度解构

## 1. 为什么传统技术文档往往充满挫败感？

在传统技术文档中，开发者经常遇到以下困境：
- 想查一个参数，却不得不阅读一篇长达 3000 字的教程；
- 想按教程上手，中途却插播了一大堆关于系统底层架构的理论解释，导致注意力严重涣散；
- 生产环境遇到了特定 Bug，翻遍文档却找不到一份聚焦解决具体问题的操作手册。

Daniele Procida 提出的 **Diataxis 框架** 彻底解决了这个结构性问题，已被 Canonical (Ubuntu)、Cloudflare、Python、NumPy 等全球顶级技术组织采纳为官方文档标准。

## 2. Diataxis 四象限正交坐标系

```
                           [理论与思考 (Theoretical)]
                                      ^
                                      |
                 Explanation          |          Reference
              (原理阐释: 理解导向)       |       (参考手册: 信息导向)
                                      |
    [服务于工作 (Work)] <---------------+---------------> [服务于学习 (Study)]
                                      |
                 How-to Guides        |          Tutorials
              (操作指南: 目标导向)       |       (上手教程: 学习导向)
                                      |
                                      v
                           [实践与行动 (Practical)]
```

### 编写法则：
1. **Tutorials (新手教程)**：像教小孩学骑自行车。用户只要按顺序做，就能体验到成功的快乐。绝对不要停下来解释“自行车的齿轮传动比物理公式”；
2. **How-To Guides (操作手册)**：像菜谱。用户想做一道“宫保鸡丁”，你只需给出材料与火候步骤，不要解释鸡的生物学起源；
3. **Reference (参考手册)**：像字典。用户查一个生词，给出精确解释与发音，零废话；
4. **Explanation (原理阐释)**：像美食评论家的一篇散文。探讨为什么法餐会选用这种酱汁，背后的历史渊源与风味平衡。
